## Why

聊天室系统（破冰期）已完成，但当前只能通过 DEV 工具手动创建用户和关系。平台缺乏真实的用户入口管道——没有注册流程、没有用户浏览列表、没有牵线发起机制。这是让整个平台从"技术演示"变为"可用产品"的关键一步：用户必须能够自主注册、浏览他人、发起匹配，才能进入已有的聊天室流程。

## What Changes

- 新增南大 smail 邮箱注册与登录认证（JWT session）
- 新增用户画像标签系统：注册时填写基本信息（年级、专业、校区），系统提取并展示兴趣标签与恋爱宣言
- 新增军师认证流程：道德问卷 + 特点问卷，信用分门槛 (>10)，失败冷却 24h
- 新增用户列表页：平铺展示带有标签和宣言的用户卡片，活跃度标识，反算法设计
- 新增牵线期流程：用户向目标发起牵线请求（消耗信用分），对方 24h 内同意则进入破冰期
- 新增最简信用分系统：签到获取、发起牵线消耗，支撑上述流程运转

## Capabilities

### New Capabilities

- `user-auth`: 南大 smail 邮箱注册、登录、JWT 认证、密码加密
- `user-profile`: 用户画像与标签系统——基本信息填写、兴趣标签提取、恋爱宣言、军师认证问卷
- `user-discovery`: 用户列表浏览与牵线发起——卡片平铺展示、活跃度标识、匿名标签、牵线请求、24h 超时机制
- `credit-system`: 最简信用分系统——签到获取、牵线消耗、余额校验

## Impact

- **后端**: 新增 Auth 模块（NestJS guard/controller/service）、User Profile 模块、Discovery 模块、Credit 模块
- **前端**: 新增注册页、登录页、用户列表页、牵线请求流程 UI
- **数据库**: User 模型已有大部分字段，可能需要新增 `declaration`（恋爱宣言）、`wingmanCertStatus`（军师认证状态）等字段；新增 `MatchRequest` 模型存储牵线请求
- **API**: 新增认证相关端点、用户浏览端点、牵线发起/响应端点、签到端点
- **依赖**: 新增 bcrypt（密码加密）、jsonwebtoken/JWT 库
