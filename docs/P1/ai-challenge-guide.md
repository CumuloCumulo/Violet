# AI需求盲区挑战 - 执行指南

## 快速开始

这是一个三步实验，用于对比AI生成的需求与真实用户调研结果的差异。

---

## 第一步：让AI生成需求（现在就可以做！）

你可以使用以下Prompt向任何AI工具（Claude、ChatGPT等）提问：

### 推荐Prompt A（完整版）

```
你是一位资深的需求分析师。请为"Violet"——一个南京大学校园恋爱顾问平台，编写完整的需求规格说明书。

项目背景：
- 大学里有很多"军师"（恋爱顾问），他们自己不参与恋爱，但乐于为他人提供恋爱咨询
- 很多学生想谈恋爱但比较腼腆，不敢主动建立关系
- Violet通过建立4人对话频道（恋爱双方+2个军师），支持军师代聊
- 学生可以通过匹配算法找到潜在恋爱对象
- 平台有虚拟货币系统，通过聊天和互动获得货币
- 军师可以自己设定聘请价格，用户用货币雇佣军师

请按以下结构输出：

1. 功能需求（至少15条，每条包含：编号、描述、优先级P0/P1/P2）
2. 非功能需求（性能、安全、可用性、可维护性）
3. 用户角色定义
4. 核心业务流程描述

请尽可能详细，每条需求应该是可测试、可验证的。
```

### 推荐Prompt B（简化版）

```
请为一个校园恋爱代聊平台生成需求列表。核心功能包括：
1. 用户匹配系统
2. 4人对话频道（2个当事人+2个军师）
3. 军师代聊功能
4. 虚拟货币系统

目标用户是大学生，请列出至少20条具体需求。
```

- 记录原始数据

## 第三步：填写对比分析表

完成调研后，使用 `ai-blindness-challenge.md` 模板填写对比分析。

---

## 对比检查清单

在对比时，重点检查以下问题：

### ✅ AI是否遗漏了...

- [ ] 隐私和安全顾虑（用户最担心什么泄露？）
- [ ] 真实社交场景中的微妙考虑（如：熟人看到怎么办？）
- [ ] 中国大学生的特殊行为模式（和国外恋爱软件的差异）
- [ ] 南大特定的校园环境因素
- [ ] 用户对付费的真实心理价位

### ✅ AI是否添加了不存在的需求...

- [ ] 过于复杂的功能（用户真的需要吗？）
- [ ] 照搬国外产品的功能（如Tinder的某些功能）
- [ ] 技术导向而非用户导向的功能

### ✅ AI的表述是否有歧义...

- [ ] "良好的用户体验" → 具体指什么？
- [ ] "快速匹配" → 多快算快？
- [ ] "安全可靠" → 具体什么措施？

---

## 示例：可能发现的AI盲区

基于类似项目的经验，AI可能会遗漏：

1. **"军师退出机制"**：军师什么时候应该退出对话？AI可能没考虑到
2. **"匹配失败的心理影响"**：被拒绝或匹配不成功的用户如何安抚？
3. **"军师责任边界"**：如果军师给出了错误建议导致纠纷，谁负责？
4. **"虚拟货币的真实价值锚定"**：货币如何兑换成实际价值？
