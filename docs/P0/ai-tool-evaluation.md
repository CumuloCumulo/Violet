## 一、AI 编程助手

### 候选工具评估

| 评估维度 | Claude Code | GitHub Copilot | Codex (OpenAI) | 通义灵码 |
|----------|-------------|----------------|-----------------|----------|
| **功能** | 终端AI编程助手，全项目上下文理解，多文件编辑，MCP协议扩展 | IDE内联代码补全，多语言支持，Chat功能 | OpenAI编程Agent，支持自然语言生成代码和自动修复 | 中文场景优化，Java/Python支持好 |
| **易用性** | 命令行交互，学习曲线较陡 | VS Code无缝集成，上手即用 | Web端/CLI，命令式交互 | IDE插件，中文友好 |
| **成本** | 需订阅Anthropic API或Claude Pro | $10/月（个人版） | 需OpenAI API额度 | 免费 |
| **团队熟悉度** | 部分成员有经验 | 多数成员熟悉 | 部分成员使用过 | 部分成员熟悉 |

### 选择结果

| 工具 | 选择与否 | 理由 |
|------|----------|------|
| **Claude Code** | **选用** | 全项目上下文理解能力强，适合复杂业务逻辑开发；终端操作适合后端NestJS场景；代码审查能力突出 |
| **GitHub Copilot** | **选用** | IDE内联补全体验流畅，适合前端React组件开发；多数成员已有使用经验，上手零成本 |
| **Codex** | **选用** | 与GPT生态协同，适合部分成员的开发习惯；自然语言生成代码能力强，可快速生成工具函数和测试代码 |
| 通义灵码 | 不选用 | 对TypeScript/NestJS等现代技术栈的支持不如上述工具；团队已有足够工具覆盖 |

**选型策略**：团队成员可根据个人开发习惯自由选择 Claude Code + GLM、Codex + GPT、或 Copilot 三条路径之一，兼顾不同成员的使用偏好，最终通过统一的代码审查流程保证代码质量。

## 四、AI 测试工具

| 评估维度 | GPT/Codex 生成测试 | GLM 生成测试 | Copilot 生成测试 | Jest + AI辅助 |
|----------|--------------------|-------------|-----------------|---------------|
| **功能** | 根据代码/需求生成测试用例和代码 | 中文需求描述生成测试用例 | IDE内根据函数签名生成 | AI生成框架+手动核心断言 |

| AI编程助手 | Codex + GPT | 代码生成、自动修复、测试代码 | 偏好OpenAI生态的成员 |
| AI编程助手 | GitHub Copilot | IDE内联补全、实时代码审查 | 偏好IDE集成体验的成员 |

| CI/CD | GitHub Actions | 自动化构建、代码风格检查 | 全员 |

### 工具搭配说明

团队成员可选择以下任一工作流：

1. **Claude Code 路线**：Claude Code（编程）+ GLM（对话），适合偏好终端开发、重视项目整体理解的成员
2. **Codex 路线**：Codex（编程）+ GPT-4o（对话），适合习惯OpenAI生态、偏好Web端交互的成员
3. **Copilot 路线**：GitHub Copilot（编程+审查），适合偏好IDE一体化体验、追求即时反馈的成员

三条路线并行，通过统一的代码审查和CI流程保证代码质量一致性。
