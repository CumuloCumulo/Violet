# AI 协作契约

**团队名称**：Violet

**日期**：2026年4月14日

---

## 第一条：AI 使用原则

1. AI 是工具，工程师是责任主体。所有使用AI辅助完成的工作，最终责任由团队成员承担。
2. 所有 AI 输出必须经过人工审查后才能合入项目。未经审查的AI生成代码、文档一律不得提交至主分支。
3. 团队成员应保持独立思考能力，避免因过度依赖AI而导致工程能力退化。
4. AI 生成的内容需与团队实际讨论结果进行对比验证，确保符合项目实际需求。

## 第二条：AI 使用范围

### 允许使用 AI 的场景

- 代码骨架和模板生成（如CRUD接口、基础组件结构）
- 文档初稿撰写（如需求文档、设计文档的框架）
- 技术方案调研与对比分析
- 代码注释和文档润色
- 测试用例生成辅助
- Bug分析和排错辅助
- 正则表达式、SQL查询等工具性代码生成

### 禁止直接使用 AI 输出（需额外审查）的场景

- 架构决策和核心技术选型（需团队讨论确认）
- 业务逻辑核心代码（如信用分结算、状态机流转）
- 安全相关代码（如认证鉴权、数据加密）
- 数据库Schema设计（需团队评审）
- API接口设计（需团队评审）

### 完全禁止使用 AI 的场景

- 团队反思日志的核心内容（需真实反思，不可由AI代写）
- 用户访谈记录和分析（需真实调研数据）
- 个人学习笔记和阶段总结
- 答辩汇报的核心内容和现场回答

## 第三条：过程记录要求

1. **Prompt 日志保留**：所有与AI的交互Prompt必须保留日志，记录在 `docs/ai-logs/` 目录下，格式为 `[阶段]-[日期]-[成员].md`。
2. **Git Commit 标注**：每次提交必须在 commit message 中标注 `[AI-assisted]`（AI辅助生成）或 `[Human-written]`（完全手写）。
3. **反思日志**：每阶段结束时，每位成员填写《AI协作反思日志》，回答以下三个问题：
   - Q1：AI在哪里帮了我？附Prompt日志与AI输出截图。
   - Q2：AI在哪里误导了我？描述发现的错误、遗漏、歧义及修正方式。
   - Q3：下次如何让AI更好地工作？提出至少一条改进措施。

## 第四条：代码合入规则

1. AI 生成的代码必须通过至少一名团队成员的 Code Review 后才能合入 `dev` 或 `main` 分支。
2. 每位成员每个编码阶段至少有 2 个完全手写的核心函数，并在代码注释中标注 `[Human-written]`。
3. Code Review 重点检查项：
   - 逻辑正确性（AI生成的代码是否存在隐藏Bug）
   - 安全性（是否存在SQL注入、XSS等安全漏洞）
   - 代码风格一致性（是否符合团队编码规范）
   - 业务逻辑准确性（是否符合需求文档描述）

## 第五条：违约处理

1. **首次违约**：由团队负责人提醒，违规成员需补充完善缺失的审查或记录。
2. **二次违约**：在团队会议上通报，违规成员需额外完成一份反思报告。
3. **严重违约**（如未经审查合入AI代码导致线上问题）：违规成员需在答辩时额外说明该问题的反思与改进措施。
4. 所有违约记录存档，作为终期评估的参考依据。
